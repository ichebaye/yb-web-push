YB Web Push Test

Стенд для проверки: может ли тап по пушу на iOS увести не в Safari/PWA, а в Яндекс.Браузер по deep link'у. Сайт полностью статический (GitHub Pages), настоящий push отправляется разовой командой с ноутбука — сервер не нужен.

1. Статус

Standalone (установлено на экран)…
Service Worker…
Notification permission…
Push подписка…
Открой этот сайт в Safari и добавь на экран «Домой» (Поделиться → «На экран Домой»), затем запусти приложение с экрана «Домой» — на iOS push и уведомления работают только для установленного PWA.

2. Подписка на push

Ключи генерируешь у себя на ноуте: npx web-push generate-vapid-keys. Приватный остаётся там же и никуда отсюда не уходит — сюда вставляешь только публичный.

5. Локальная проверка (без push)

    
Быстрый способ проверить только сам переход по тапу: уведомление показывается через registration.showNotification(), а дальше срабатывает тот же notificationclick. Это всегда классический (императивный) путь — декларативный так не воспроизвести.

    

      
    

  


  

    
6. Лог событий (IndexedDB)

    
Как читать: если в логе есть push-received — Safari не распознал декларативный формат и свалился в обычный, императивный путь. Если сразу redirect-page-loaded без push-received и notificationclick — сработал именно декларативный путь.

    
Service worker и redirect-страница пишут сюда диагностику вместо похода на сервер, потому что после открытия стороннего браузера JS-контекст PWA пропадает — а локальная база остаётся и читается при следующем открытии.
